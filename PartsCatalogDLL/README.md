# Parts Catalog 
Десктопное приложение для управления иерархическим каталогом деталей с динамическими атрибутами. Проект реализует паттерн Entity-Attribute-Value (EAV) для гибкого хранения характеристик деталей различных категорий.

## 🛠 Технологический стек

- **Язык**: Delphi (Object Pascal)
- **Фреймворк UI**: VCL + DevExpress VCL Subscription (`TcxVirtualTreeList`, `TdxLayoutControl`, `TcxTextEdit`, `TcxDateEdit`, `TcxCheckBox`, `TcxComboBox` и др.)
- **СУБД**: PostgreSQL 12+ (используются ENUM, CHECK-ограничения, триггеры)
- **Доступ к данным**: FireDAC (`TFDConnection`, `TFDQuery`, `TFDTransaction`)
- **Вспомогательные библиотеки**: `cxVirtualTreeListHelper.pas` (кастомная типобезопасная обертка над `TcxCustomDataSource`)

## 🏗 Архитектурные особенности

### 1. Работа с деревом и списками (DevExpress)
Используется нативный `TcxVirtualTreeList` в связке с кастомным дженерик-хелпером `cxVirtualTreeListHelper.pas`. 
- **`TVTSmartDataSource<TCategoryNodeData>`**: Реализует **ленивую загрузку (SmartLoad)** дерева категорий "сверху-вниз". Дочерние узлы загружаются из БД только при раскрытии родительского узла (событие `OnExpanding`), что экономит память и ускоряет отклик.
- **`TVTLoadAllDataSource<TPartNodeData>`**: Управляет плоским списком деталей выбранной категории. Данные инкапсулированы внутри узлов (`TDictionary<string, string>` для значений атрибутов), что обеспечивает полную самодостаточность узла и корректную работу методов `GetValue`/`SetValue`.

### 2. Динамическое создание полей ввода (`fPartEdit.pas`)
Форма редактирования детали использует `TdxLayoutControl` для автоматического выравнивания элементов. 
- Поля создаются динамически на основе атрибутов выбранной категории (`TcxTextEdit` для строк/чисел, `TcxDateEdit` для дат, `TcxCheckBox` для булевых значений).
- **Важно**: `TdxLayoutControl` управляет позиционированием *внутри* себя, но **не изменяет автоматически размер самой формы (`ClientHeight`)**. Поэтому при динамическом добавлении контролов применяется ручной расчет `YPos` и последующее изменение `ClientHeight` формы, чтобы все сгенерированные поля гарантированно были видны пользователю и не обрезались.

### 3. Целостность данных на уровне СУБД
Бизнес-правила продублированы в PostgreSQL для защиты от некорректных данных:
- `chk_single_value`: CHECK-ограничение, гарантирующее, что в таблице `part_values` заполнено ровно одно поле значения (соответствующее типу атрибута).
- Триггер `trgfn_check_required_attributes`: Проверяет заполнение всех обязательных атрибутов перед `INSERT`/`UPDATE`.
- Триггер `trgfn_check_value_type`: Запрещает запись значения несоответствующего типа (например, текста в числовое поле).

### 4. Разделение ответственности
- **UI Forms**: Отвечают только за отображение и сбор данных с контролов.
- **`TCatalogService`**: Инкапсулирует всю бизнес-логику и работу с FireDAC, возвращая в UI готовые массивы записей или примитивные типы.
- **`uEntities`**: Содержит легковесные классы-модели и классы узлов для DevExpress, не зависящие от UI.

### 5. Поддержка скинов DevExpress

Приложение поддерживает динамическую смену тем оформления:
- **Компонент управления**: `TdxSkinController` (размещен в `dmDatabase`).
- **Список скинов**: Заполняется через `cxLookAndFeelPaintersManager.PopulateSkinNames`.
- **Применение скина**: Изменение `RootLookAndFeel.SkinName`.

## 🚀 Инструкция по запуску и сборке

### Предварительные требования
1. **Delphi**: Версия 10.4 Sydney или новее (с поддержкой Generics и UTF8).
2. **DevExpress VCL**: Установлен и прописан в Library Path (версии 20.2 или новее).
3. **PostgreSQL**: Запущенный сервер версии 12+.
4. **FireDAC**: Настроен драйвер `PostgreSQL` (файлы `libpq.dll`, `libcrypto-1_1.dll`, `libssl-1_1.dll` находятся в папке `Exe/` или в системном `PATH`).

### Настройка базы данных
1. Создайте базу данных в PostgreSQL (например, `parts_catalog`).
2. Выполните скрипт `SQL/schema.sql` для создания таблиц, ENUM-типов, индексов и триггеров.
3. При необходимости наполните БД тестовыми данными или используйте функцию импорта из XML.

### Настройка подключения в приложении
1. Откройте проект `Source/TestTask.dproj` в Delphi IDE.
2. Откройте модуль `dmDatabase.pas`.
3. В инспекторе объектов для компонента `FDConnection` (или в коде) укажите актуальные параметры подключения:
   - `Database`: имя вашей базы данных
   - `User_Name`: пользователь (по умолчанию `postgres`)
   - `Password`: ваш пароль
   - `Server`: адрес сервера (например, `localhost`)
   - `Port`: порт (по умолчанию `5432`)

### Сборка и запуск
1. Нажмите **Run (F9)** в среде Delphi.
2. Приложение проверит подключение к БД при запуске. В случае ошибки будет выведено соответствующее сообщение.
3. Для импорта тестовых данных используйте кнопку "Импорт из XML" и выберите файл `Exe/sample_catalog.xml`.

## 🔄 Импорт и Экспорт XML
- **Импорт**: Поддерживает вложенную структуру категорий. Реализована upsert-логика: если категория или деталь с таким кодом уже существует, она обновляется, иначе создается новая.
- **Экспорт**: Формирует валидный XML-файл со всей иерархией категорий, определениями атрибутов и значениями деталей.

## 📝 Примечания для разработчиков
- При добавлении новых типов атрибутов необходимо обновить: 
  1. ENUM `TAttrType` в `uEntities.pas` и в БД (`schema.sql`).
  2. Логику создания контролов в `fPartEdit.pas.BuildControls`.
  3. Логику валидации в `fPartEdit.pas.ValidateAndSave`.
- Файл `cxVirtualTreeListHelper.pas` является ключевым для работы дерева. Не удаляйте его и не заменяйте на прямую работу с `TcxCustomDataSource` без веских причин, так как он обеспечивает типобезопасность и автоматическое управление памятью узлов.
- В папке `Source/__history` и `Source/Win32/Debug` находятся временные файлы компиляции и резервные копии, их можно безопасно игнорировать или удалять.
