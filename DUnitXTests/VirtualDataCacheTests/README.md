# Тесты для TVirtualDataCache (DUnitX)

Этот проект содержит набор модульных тестов (Unit Tests) для компонента `TVirtualDataCache`, реализованный с использованием фреймворка **DUnitX** в среде Delphi.

## 🎯 Назначение
Проект предназначен для проверки корректности работы виртуального кэша данных, включая:
- Инициализацию и управление состоянием (страницы, параметры SQL, счётчики).
- Логику попадания и промаха кэша (`GetRecord`).
- Механизм вытеснения страниц по алгоритму LRU (`EnforceCacheLimit`).
- Потокобезопасность при одновременном чтении и модификации кэша из нескольких потоков.
- Корректную обработку граничных условий (отрицательные индексы, выход за пределы страницы, пустой кэш).

## 📁 Структура проекта
- `VirtualDataCacheFixture.dpr` — главный файл проекта исполняемого файла тестов.
- `uVirtualDataCacheFixture.pas` — основной модуль с реализацией всех тестовых сценариев.
- `exe/` — каталог для выходных файлов сборки (включая `dunitx-results.xml`).
- `Win32/` — каталог с промежуточными файлами компиляции.

## ⚙️ Особенности реализации тестов

### 1. Изоляция от базы данных
Тесты спроектированы так, чтобы не требовать реального подключения к БД. Для этого используется:
- Метод-хелпер `InjectPage`, который напрямую добавляет страницы в словарь `FPages` и обновляет LRU-очередь, минуя асинхронный `DoLoadPage`.
- Фиктивная функция маппинга `MockMapFunc`, передаваемая в конструктор для удовлетворения сигнатуры, но не вызываемая в ходе тестов.

### 2. Доступ к protected-членам (Re-export Pattern)
Для проверки внутреннего состояния кэша без использования RTTI применяется классический паттерн Delphi:
```pascal
TTestVirtualDataCache = class(TVirtualDataCache<TMockRecord>)
public
  property Pages;            // Делает protected FPages доступным для чтения
  property LoadingPages;     
  property PageAccessOrder;  
  property FailedPages;      
  property SQLParams;        
  property SQLTemplate;      
  procedure ExposedEnforceCacheLimit; // Обёртка для вызова protected-метода
end;
```

### 3. Корректная многопоточность (Исправление захвата переменных)
В тесте `ThreadSafety_ConcurrentAccess_NoAV` ранее присутствовала классическая ошибка захвата переменной цикла в анонимных методах Delphi (все потоки получали последнее значение итерации). 

**Решение:** Введена вспомогательная функция `CreateWorkerThread`, которая принимает индекс потока по значению, гарантируя корректный захват переменной для каждого анонимного метода:
```pascal
function CreateWorkerThread(AThreadId: Integer): TThread;
begin
  Result := TThread.CreateAnonymousThread(
    procedure
    begin
      // AThreadId корректно изолирован для каждого потока
      case AThreadId of ...
    end
  );
end;
```

### 4. Обработка асинхронных операций
Тесты, инициирующие фоновую загрузку (`RequestPage`, `CreatePlaceholderRecord`), используют проверку конечных состояний (`LoadingPages.ContainsKey` или `Pages.ContainsKey`) вместе с небольшой задержкой (`Sleep`), чтобы дождаться реакции планировщика потоков, избегая хрупких проверок временных состояний.

## 🚀 Как запустить тесты

1. Откройте проект `VirtualDataCacheFixture.dproj` в Delphi IDE.
2. Убедитесь, что путь к исходному коду `VirtualDataCache.pas` корректно указан в `Search Path`.
3. Выполните **Build** (Shift+F9) для полной пересборки проекта.
4. Запустите проект (F9). 
5. Результаты тестов будут выведены в консоль, а также сохранены в файл `exe\dunitx-results.xml`.

> **Важно:** Перед запуском убедитесь, что файл `dunitx-results.xml` не открыт в других программах (например, в браузере или редакторе), чтобы избежать ошибок блокировки файла при записи.
