# Схема базы данных «Каталог деталей»

## ER-диаграмма (текстовая)

    categories (1) ──< (N) categories          (иерархия, parent_id)
    categories (1) ──< (N) attribute_defs      (атрибуты категории)
    categories (1) ──< (N) parts               (детали категории)
    parts        (1) ──< (N) part_values       (значения атрибутов)
    attribute_defs (1) ──< (N) part_values

## Таблицы

### categories
Хранит иерархию категорий. Поддерживает неограниченную вложенность.
- `parent_id` — ссылка на родительскую категорию (NULL = корень)
- Уникальность: `(parent_id, name)` — в рамках одного родителя имена не повторяются

### attribute_defs
Шаблоны атрибутов, привязанные к категории. Определяют, какие атрибуты
должны иметь детали данной категории.
- `attr_type` — тип значения: string | number | date | boolean
- Удаление запрещено (ON DELETE RESTRICT) — по требованию ТЗ

### parts
Детали каталога.
- `code` — глобально уникальный код детали (UNIQUE)
- `category_id` — категория (ровно одна, NOT NULL)

### part_values
Значения атрибутов деталей в формате EAV.
- Первичный ключ: `(part_id, attribute_id)`
- CHECK-ограничение гарантирует, что заполнена ровно одна колонка значения
- Триггер `trg_part_values_check_type` проверяет соответствие типа

## Целостность данных

1. **Обязательность атрибутов** — constraint trigger `trg_parts_check_attrs`
   проверяет, что для каждой детали заполнены все атрибуты её категории.
2. **Соответствие типов** — триггер `trg_part_values_check_type`
   не позволяет записать строку в числовое поле и т.п.
3. **Запрет удаления** — категории, атрибуты и детали нельзя удалить,
   если на них есть ссылки (ON DELETE RESTRICT).

## Индексы

- `idx_categories_parent` — быстрый поиск детей узла
- `idx_attribute_defs_category` — быстрый список атрибутов категории
- `idx_parts_category` — детали категории
- `idx_parts_code` — поиск детали по коду (для импорта)

## Представления

- `v_parts_full` — денормализованный вид для отчётов и выгрузок
